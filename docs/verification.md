# WordPressでの最終確認

レクチャーと進捗削除ボタンは、ページ設定からそれぞれON/OFFを切り替えられます。

## 準備

1. 制作中データを「JSONで保存」からバックアップします。
2. ページ設定の進行保存用キー名に、他の記事と重複しない値を設定します。例：`test-episode-001`。
3. タイトル → テキスト → 回答欄 → テキスト → 進行ボタン → テキストの順で追加します。
4. 回答候補に「いちご」を登録します。回答欄とボタンのアクションは「次のブロックを表示する」にします。
5. コード書き出しで指摘された入力不備を直し、HTMLとJavaScriptを両方ともWordPressのテキストモードへ貼り付けます。

## 表示と進行

- 通常：最初の回答欄まで表示され、正解すると進行ボタンまで、ボタンを押すと最後まで表示される。
- スクロール：画面内に入ると表示される。未突破の回答欄や進行ボタンより後ろは表示されない。
- タップ／タップ＋：クリック・タップごとに進み、未突破の回答欄・進行ボタンで停止する。タップ＋のみ出現時にフェードする。
- RPG：吹き出しは文字送り、タイトル・テキストは個別設定どおり。文字送り中の操作は全文表示だけを行い、次のグループには進まない。
- 同時表示ONの連続するブロックは同じグループになる。ただし未突破ロックを越えて表示しない。
- PCは「クリック」、スマートフォンは「タップ」と表示され、スマートフォンの案内文字は24px（PC16px）になる。

## 回答とボタン

- 「イ チ ゴ」「い　ちご」で正解し、空欄・別の単語では進まない。
- 単一選択はセレクトボックスで表示され、設定した1つの正解だけで通過する。
- 複数選択は正解の全項目だけを選んだ場合に通過する。選び不足・選び過ぎは不正解になる。
- 多答回答は全欄正解で通過する。判定中は2秒間Progress Activityアイコンが回転し、終了後に不正解欄が揺れる（横揺れONの場合）。正解済みの欄は編集不可になり、不正解の欄だけを修正できる。
- 単一・多答とも、再送信前に前回の不正解メッセージが消え、判定後に再表示される。全問正解後は入力・送信できず、再訪問時も固定される。
- 個別判定の表示ON/OFF、不正解メッセージ、横揺れON/OFFが反映される。
- リンク指定の回答・ボタンは、指定先に同じタブで遷移する。

## 保存・復元

- アプリをリロードすると、編集データ・順序・選択中ブロックが戻る。
- JSONを保存して読み込み直すと、全8種類の設定とキャラクター情報が戻る。
- WordPress記事で途中まで進めてリロードすると、突破したロックを維持する。タップ／RPGは閲覧済み部分を全文表示し、再開位置へスクロールする。
- 未突破の回答欄を前へ並び替えて再書き出しすると、その回答欄で止まる。削除したブロックの過去の進捗は無視する。
- 最初から試し直すときは、テスト用の進行保存用キー名を変更して再書き出しする。他の記事のキーは変更しない。

制作データと記事の閲覧進捗は別の保存先です。アプリ内プレビューは、編集中のスクロール位置・進行状態を一時的に引き継ぎます。閲覧進捗を永続保存せず、表示モード・PC/SP・全ロック解除の切り替え時には初期状態へ戻します。

## デザイン

PC・スマートフォンの両方で、吹き出し3テーマ、カードの色・角丸・アイコン、画像の幅、フォームの配置、18pxのブロック間余白を確認してください。通常・角丸のキャラクター名は本文の上です。

## 自動確認の範囲

`npm run lint`、`./node_modules/.bin/tsc --project tsconfig.app.json --noEmit`、`node --test tests/*.test.mjs`で静的検証・生成コード・表示制御を確認します。NodeテストのDOMは模擬実装のため、実ブラウザの描画、WordPressのテーマとの最終的なスタイル競合、端末操作までは確認していません。

## フォントと全ロック解除プレビュー

- ページ設定・各ブロックでGoogle Fontsの日本語68ファミリーを選択できる。カードはタイトルと本文を個別に設定できる。
- 使用するファミリーの提供ウェイトをすべて読み込み、JSONにも選択を保存する。フォント一覧は公式メタデータ（2026-09-30時点）のスナップショット。
- プレビューの「全ロック解除」をONにすると、表示モードや正誤にかかわらず全ブロックを即時表示する。回答判定自体は試せる。
- OFFに戻すと初期状態から通常の進行になる。解除設定はJSON・WordPress書き出し・閲覧進捗には保存しない。

## スマホ寸法・フォント見本・自動表示

- スマホは文字・キャラクター画像・画像の最大幅・余白・枠・フォーム寸法をPC基準の1.5倍にする。横幅100%の部品は親幅を維持し、画像も親幅を超えない。ブロック間余白はPC18px／SP27px。
- フォント候補の名前にそのフォントを適用する。太さの候補は対応ウェイトだけをThin／Regular／Bold等で表示し、見た目にも太さを反映する。
- 「ページ設定を使用」ではページフォントの対応ウェイトを使用する。非対応の既存ウェイトは表示・書き出し時に最も近い対応ウェイトへ補正する。
- RPGモードで「前の文字送りが終了とともに表示」をONにすると、直前の表示グループの文字送り完了後に自動表示する。全文表示操作でも同じ動作。直前に文字送り対象がなければ即時進む。
- 「前の出現と同時に表示」と新設定は排他。どちらもOFFなら従来どおりタップ待ち。新設定は旧JSONを読み込んだ場合もOFF。
- 回答欄・進行ボタンの未突破ロックは自動表示でも越えない。通常・スクロール・タップモードでは新設定を無視する。

## スクロールと初期フォント

- RPG／タップ／タップ＋で次を表示した際、画面外にはみ出すときだけスクロールする。長いブロックは先頭、短いブロックは下端まで見える位置に調整する。
- 要素を編集してプレビュー文書が更新されても、表示済みブロック・突破状態・スクロール位置を引き継ぐ。編集によって本文が短くなった場合はスクロール可能な範囲に収まる。
- 左のブロック一覧は新規追加・複製時に下端へスクロールする。
- 新規タイトル・テキストのフォントは「ページ設定を使用」。既存ブロックの個別指定は維持する。

## レクチャーと進捗削除

- レクチャーONで初期文言入りの編集欄を表示し、出力本文の先頭に案内を表示する。OFFでも編集済みの文言は保持する。
- 「デフォルトの文言に戻す」で確認ダイアログを表示する。キャンセルでは変更せず、OKで初期文言に戻す。
- 「進捗削除ボタンの設置」はアニメーションモード直下。通常モードでも回答欄・進行ボタンがあれば切替可能。
- 進捗保存用キーを設定してONにすると、本文最下部に「このページの進捗を削除」を表示する。タップ進行の途中でも表示する。
- 削除確認をキャンセルするとそのまま。OKではこのページのキーだけを削除して再読み込みする。他の記事の進捗・制作データは削除しない。
- プレビューでは親画面で確認し、プレビュー内の一時的な進捗だけを初期化する。
